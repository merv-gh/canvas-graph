## Discoverability/self-operability finding

Without repository guidance, DeepSeek opened the front door, ran doctor, and observed
honest `context` abstention, but spent the remaining calls in `query` and never found a
valid `explore artifact-plan` operation. Two deterministic samples scored 40/100.

Actionable standalone-product improvements:

1. On context abstention, print one exact `explore artifact-plan -kind concept ...`
   next command.
2. Put durable artifact planning in the primary help, not only behind `explore` error
   discovery or MCP schemas.
3. Make `explore file` errors show the required `-file` form.
4. Let `path` use the detected source root; its current default of `src` loses anchors
   in this `frontend/` repository unless `-root frontend` is supplied.
5. Offer a native saved-recipe command that keeps the stable stage-shaped interaction
   without a harness adapter.
6. Index exported classes and `export const ... =` functions as concept source anchors.

## Strict concept-scoped finding

The stricter harness removes maintainer context, reference code, source templates, and
change plans. A cold model can write only structured concepts; a fresh model can read and
edit only paths declared by those concepts; every source write is native plan/apply; the
gate requires hidden acceptance plus at least 99% statements, branches, functions, and
lines for the backend and canvas automation modules.

The first sample did not pass and is not presented as a winner:

- its old author prompt still suggested three concern categories, so it was only partly
  autonomous; the maintained prompt now derives decomposition from the task;
- two concepts materialized, while the future-file-only backend concept did not;
- the first implementation attempt exposed clipped-read repetition; concept reads now
  support bounded ranges;
- the retry made 19 concept-scoped reads, 5 invalid calls, and no source edit before
  DeepSeek returned HTTP 402;
- both local API env sources resolve to the same exhausted credential;
- independent scoring failed focused feature tests, both hidden acceptance suites, and
  feature coverage (0 instrumented lines).

No 99% result is claimed. The next funded `make experiments` run executes the corrected
task-only/ranged-read protocol.

The independent reference does pass the literal gate: 283/283 statements, 81/81
branches, 77/77 functions, and 230/230 lines, plus focused/type/full/hidden acceptance.
The refreshed saved recipe reproduced that result through verified native plan/apply in a
fresh worktree. This proves feasibility only; it is not credited to the cold model trial.

## Self-improvement cycle

For every new feature: route the task; author and natively validate concepts before code;
require frontend/backend/test ownership; allow only concept-scoped native plan/apply;
verify hidden behavior and 99% feature coverage; add landed symbols; measure reads,
invalid calls, tokens, and repairs; then improve concepts/tooling before the next feature.
Extra exploration is treated as a projection defect, not forgotten session cost.
