# Fairness assessment — 2026-07-19

## Verdict on the earlier “winner”

The recipe-driven result was not a fair discoverability or autonomous-editing win.
A maintainer supplied the target concept, a reference-derived full change recipe, and
the exact native plan/apply sequence. It fairly measured recipe replay/compression, but
not whether file-projections could make an unfamiliar model discover and implement the
feature. The separate raw discoverability score (40/100) remains the honest autonomy
signal.

## Strict protocol

The replacement protocol removes maintainer context, reference code, source templates,
and change plans. A cold model may write only structured `concepts/*.yaml` through
native artifact plan/apply. A fresh model receives only the task plus those concepts.
Repository reads and writes must name a concept; paths are mechanically limited to that
concept's inputs/outputs/ownership; every edit uses native change plan/apply. Final
scoring independently requires focused tests, typecheck, full Vitest, hidden acceptance,
and at least 99% statements, branches, functions, and lines on both automation feature
files.

Write authority is the intersection of exact file paths declared by a concept and the
fixed automation evaluation surface. Directory-wide ownership cannot expand authority.

The backend public result shape is now explicit in `task.md`; hidden tests no longer
depend on an undocumented reference-only naming choice.

## First strict sample: limitations counted, not repaired

`strict-concepts-3` is useful evidence but not the final clean sample:

- its older author prompt suggested the three desired concern categories, so concept
  decomposition was partly scaffolded even though fields, symbols, and handoffs were
  model-authored;
- 2/3 concepts materialized; the future-file-only backend concept was unknown to native
  architecture;
- the first implementation attempt exposed an unbounded/clipped read loop; the harness
  now requires ranged reads for large concept-owned files;
- the fresh retry made 19 concept-scoped reads, 5 invalid calls, and zero source edits;
- DeepSeek then returned HTTP 402. Both discovered `.env` API sources contain the same
  credential, so no independent local key remained;
- independent scoring correctly failed: no focused feature tests, no feature coverage,
  and both acceptance suites failed.

Because provider balance stopped the clean rerun, no 99% win is claimed. The next run of
`make experiments` uses the task-only concept-author prompt and the ranged-read fix.

## Gate feasibility control

An independently completed reference was raised to 100% in all four coverage dimensions,
saved into the native recipe, replayed into another clean worktree, and passed focused,
typecheck, full-suite, hidden UI, and hidden backend gates. This proves the strict gate and
recipe are viable; it is deliberately reported without model read/token numbers and does
not repair the failed cold-agent result. See `REFERENCE-BASELINE-2026-07-19.md`.

Local-model substitution was rejected as result evidence: Qwen 3.5 9B timed out before a
tool call and Qwen 2.5 Coder 3B emitted tool-shaped JSON as text instead of a protocol tool
call. Those smoke probes only confirm that replacing DeepSeek would change the measured
system.
