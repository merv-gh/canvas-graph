Verdict

The interaction model is coherent both at rest and in transition. The top toolbar stays fixed, the left rail owns navigation and advanced properties, mode switches replace contextual styling without collapsing the catalog, and contextual actions stay close to the object.

The last acceptance gaps are closed: menus take and restore focus correctly, description editing is explicit, phone drawers behave as modal sheets, and hamburger/Fit controls use identical measured geometry.

Should every property move into context menus?

No—not into the menu itself. The mouse-travel diagnosis is right; the proposed container is too fragile. Context menus are transient action lists. Textareas, structure editors, multi-select values, and long option groups turn them into accidental inspectors, break familiar menu keyboard semantics, and make outside-click dismissal risky.

The stronger next iteration is a hybrid: keep Rename, Edit description, toggle state, common style swatches, convert, fold, and delete near the pointer; let Details open a compact anchored property popover beside the selected node; allow that popover to expand or pin into the left inspector for advanced and multi-line fields. This removes most cross-screen travel without forcing every field into one ephemeral surface.
